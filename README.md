# Forkcast

An AI meal-planning web app that recommends recipes from what's already in your pantry.

You keep a running list of ingredients, and Forkcast suggests meals built around them. It checks each recipe's nutrition against a real food database instead of trusting the AI's guess, and tracks what you eat against your daily targets. When you skip a meal or go off-plan, it adjusts the rest of your day. It also tells you what to buy to fill the gaps.

> **Status:** in active development. Auth and pantry management are built; the AI recommendation pipeline is next. See [Roadmap](#roadmap).

## Features

| Feature | What it does | Status |
|---|---|---|
| Accounts | Register, sign in, stay signed in for 24h | Done |
| Pantry | Add, edit and remove ingredients, with search-as-you-type | Built, in testing |
| Recipe recommendations | Three options per meal, generated by an LLM from your pantry, goals and remaining macros, with nutrition verified by Spoonacular | Planned |
| Nutrition tracking | Log meals and see daily and weekly calories, protein, carbs, fat and fibre | Planned |
| Adaptive rebalancing | Recalculates the remaining meals after a skipped or unplanned meal | Planned |
| Shopping list | Lists what the plan needs that the pantry doesn't have | Planned |

## Tech stack

- **Frontend:** React, Vite, Tailwind CSS, React Router, Axios
- **Backend:** FastAPI (async), SQLAlchemy 2.0 async ORM, Alembic, Pydantic
- **Data:** PostgreSQL, Redis (caches nutrition API responses)
- **AI:** LangChain with an OpenAI or Anthropic model
- **External API:** Spoonacular for ingredient search and verified nutrition
- **Auth:** JWT with bcrypt password hashing

## Architecture

```
React (Vite) ──HTTPS + JWT──▶ FastAPI
                                 │
        auth · pantry · recommendation · nutrition · rebalance · shopping list
                                 │
            PostgreSQL        Redis cache        LLM API · Spoonacular
```

Each feature is a separate service module. Route handlers only validate input and call those services. The AI step sits behind its own interface, so a trained recommendation model can replace it later without touching the rest of the system.

## Running locally

**Prerequisites:** Python 3.12, Node 20.19+ (not 24), Docker Desktop, and a free [Spoonacular](https://spoonacular.com/food-api) API key.

```bash
# 1. Databases (Postgres on host port 5433, Redis on 6379)
docker-compose up -d

# 2. Backend
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r backend/requirements.txt
cd backend
# create backend/.env (see below), then:
alembic upgrade head
uvicorn app.main:app --reload --port 8000

# 3. Frontend (new terminal)
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

`backend/.env`:

```
DATABASE_URL=postgresql+asyncpg://forkcast:forkcast@127.0.0.1:5433/forkcast
REDIS_URL=redis://localhost:6379
JWT_SECRET=<random string, 32+ chars>
OPENAI_API_KEY=<key>
SPOONACULAR_API_KEY=<key>
```

The API docs are at http://localhost:8000/docs once the backend is running.
